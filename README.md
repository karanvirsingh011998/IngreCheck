# IngreCheck

Scan ingredients. Know instantly.

IngreCheck is a React Native app for reading packaged-food barcodes. It looks up the product in Open Food Facts, then explains recognized ingredients from a local knowledge base. An account is optional and is only used to show a profile.

The app is meant to be run as a native development build. Do not use Expo Go.

## Requirements

- macOS
- Node.js 22.13 or newer
- Xcode and an iOS Simulator, or a physical iPhone, for iOS
- Android Studio, the Android SDK, and an emulator or a physical Android phone, for Android

This machine may still default to an older Node. Use Node 22 before installing or building:

```bash
nvm use 22
node -v
```

## Install

```bash
npm install
npx expo-doctor
```

`npm install` installs the Expo SDK and the packages already pinned in `package.json`. You do not need a second install unless `npx expo-doctor` tells you a package is missing.

## Run on iOS

1. Install Xcode from the Mac App Store and open it once so it can install the command-line tools.
2. In Xcode, sign in with an Apple ID if you want to run on a physical iPhone. A simulator does not need a paid developer account.
3. From this folder:

```bash
npx expo run:ios
```

That command generates the `ios` project if needed, compiles it, and installs the app on the simulator.

The iOS Simulator camera usually cannot scan a barcode the way a phone can. On the simulator, use **Enter a barcode**. A useful test code is `3017620422003`.

On a physical iPhone:

```bash
npx expo run:ios --device
```

The first build asks for camera permission. The camera is used only to read the barcode on the device. Images are not uploaded.

## Run on Android

1. Install Android Studio.
2. In Android Studio, install an Android SDK and create a virtual device, or enable USB debugging on a phone.
3. From this folder:

```bash
npx expo run:android
```

On a connected phone, the same command installs the development build when a device is selected.

Android camera permission is added by the Expo Camera config plugin. Audio recording is not requested.

## Native projects

`ios/` and `android/` are generated by Expo. Do not edit them by hand. After changing `app.config.ts`, plugins, or native dependencies, regenerate them:

```bash
npx expo prebuild
```

Use `npx expo prebuild --clean` when a native project is stale. Then run `npx expo run:ios` or `npx expo run:android` again.

## Optional profile

Scanning works with no account. Profile sign-in uses Supabase email, Google, and Apple. Copy the example env file and fill in the values from your Supabase project:

```bash
cp .env.example .env
```

```
EXPO_PUBLIC_SUPABASE_URL=
EXPO_PUBLIC_SUPABASE_ANON_KEY=
EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=
EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID=
EXPO_PUBLIC_GOOGLE_IOS_URL_SCHEME=
EXPO_PUBLIC_PREMIUM_MODE=disabled
```

`EXPO_PUBLIC_PREMIUM_MODE` is `disabled`, `demo`, or `production`. `disabled` hides the Premium screen. `demo` unlocks extended history on this device for testing. `production` shows the Premium information screen and keeps the free history limit. The app never treats a local flag as a paid subscription.

Use the anon key, not the service-role key. `.env` is gitignored.

### Cloud history, favorites, and preferences

Install is already included in `npm install`. The extra package for a saved product copy is:

```bash
npx expo install @react-native-async-storage/async-storage
```

After you fill `.env` and run the SQL below, restart the existing development build:

```bash
npx expo start --dev-client
```

These screens are JavaScript. They use the development build you already installed. A new native binary is required only if that build was created before AsyncStorage was added.

In the Supabase SQL Editor, paste and run `supabase/migrations/20261009140000_phase2_user_data.sql`. That creates `profiles`, `scan_history`, `favorite_products`, and `ingredient_preferences`, turns on row level security, creates a profile when someone signs up, and adds `delete_own_account()`. If Supabase rejects that function, delete the account from Authentication in the dashboard. The app shows those steps and does not use a service-role key.

This repository does not apply that SQL for you, and unit tests do not prove the policies. Check them with two real accounts:

1. Sign in as Account A and save a scan, a favorite, and an ingredient preference.
2. Sign out and sign in as Account B.
3. Account B’s history, favorites, and preferences must be empty.
4. Account B must not be able to read or change Account A’s rows. In the SQL Editor, `auth.uid()` is empty, so use the app or an authenticated request as Account B.
5. Delete Account A from the profile screen, or from Authentication if the app reports the dashboard steps. Account A’s rows should disappear with the user.

In the Supabase dashboard:

1. Enable the Email, Google, and Apple providers.
2. Add redirect URLs `ingrecheck://auth/callback` and `ingrecheck://auth/reset`.
3. For Google, create a web client ID and put it in both Supabase and `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`. Create an iOS client ID for the bundle ID `com.ingrecheck.app`, and set `EXPO_PUBLIC_GOOGLE_IOS_URL_SCHEME` to the reversed client ID (`com.googleusercontent.apps...`). For Android, add the debug SHA-1 of this build to the Android client.
4. For Apple, enable Sign in with Apple on the bundle ID and add that bundle ID to the Supabase Apple client IDs.

Google and Apple buttons stay in the app, but they cannot finish until those credentials exist. Rebuild the native app after changing the Google iOS URL scheme, because that value is written into the iOS project at build time.

## What this version includes

- Home screen with scan and manual barcode entry
- On-device barcode scanning for EAN-13, EAN-8, UPC-A, and UPC-E
- Open Food Facts API v3 lookup, shared by the camera and the typed barcode
- Product name, brand, photo, category, and country when the record has them
- Original ingredient text plus local explanations for recognized ingredients
- Nutrition per the source basis, with salt and sodium kept separate
- Listed allergens, possible traces, and a note to check the package
- NOVA group only when the product record includes 1, 2, 3, or 4
- Optional Supabase profile with email, Google, and Apple
- Scan history, favorites, and ingredient preferences for a signed-in account
- A Premium information screen with proposed test prices and no checkout
- Loading, permission, not-found, offline, timeout, and malformed-data states

## Known limitations

- The ingredient explanations cover a small curated list. Unknown names stay unknown.
- Open Food Facts records can be incomplete or different from the package you are holding.
- Scan history, favorites, and preferences stay empty until the SQL above has been run and the account is signed in.
- Row level security is not verified by the unit tests. Use the two-account checklist above.
- Premium prices are proposed test prices. There is no checkout and no restore-purchases flow.
- Product comparison is not in this version.
- Google and Apple sign-in need the dashboard setup above. Email sign-in also needs a Supabase project.
- The iOS Simulator is a poor test of the camera. Confirm scanning on a phone.
- This version does not claim a health score, and it does not detect contaminants from a barcode.
